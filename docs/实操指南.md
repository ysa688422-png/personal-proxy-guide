# 从零搭建东京和新加坡双线路

完成后，一部手机或一台电脑导入一次配置，就能选择东京、新加坡两个出口。你可以用浏览器查到的公网 IPv4，与 AWS 中的静态 IPv4 逐一核对。先准备一台测试设备，保留日常使用的设备和连接。

本案例最初在新加坡搭建 WireGuard，后来为多平台和双线路切换增加了 Hysteria 2；两种协议可以在不同 UDP 端口上共用一台实例。这里的双线教程可独立运行，采用 Hysteria 官方 Linux 服务端复现；原部署使用的 sing-box 服务与其配置文件各有自己的格式。只想先搭一个系统级 VPN 的读者可从[单节点 WireGuard 教程](WireGuard.md)开始。

## 1. 准备 AWS 账户和云主机

首次开户时，进入 [AWS 注册页](https://signin.aws.amazon.com/signup)。使用自己的邮箱、真实联系及账单资料，在 AWS 页面完成邮箱、付款方式和身份验证。选择符合自己预算的账户计划及支持方案，收到激活通知后登录控制台。在右上角账号菜单进入 **Security credentials → Assign MFA device**，按页面提示绑定验证器或通行密钥。已有账户可以直接核对 MFA 和计划。

1. 登录你自己的 AWS 账户并完成 MFA。在 **Billing and Cost Management** 查看账户计划、可用抵用金及其到期日，再看免费计划结束日期。如要求现金支出为零，只在账户页面明确说明计划和可用服务满足要求时继续；遇到升级付费计划的提示，先停在此处。
2. 打开 **Lightsail → Create instance**，选择 **Singapore（ap-southeast-1）→ Linux/Unix → OS Only → Ubuntu 24.04 LTS**，选择支持公网 IPv4 的双栈套餐。以创建页面所示的月价、流量额度及优惠为准。为实例取你自己的名字。在该区域保存 SSH 登录方式。
3. 一台验证通过后，再用相同步骤在 **Tokyo（ap-northeast-1）** 建第二台。两地分别计费。若创建页显示同规格每台每月 7 美元，两台持续运行整月的套餐费示例为 **14 美元**；税、超额出站流量和额外资源另计。实例停机期间仍可能计费。付款与免费资格以你的账单为准。[Lightsail 定价](https://aws.amazon.com/lightsail/pricing/) · [AWS 免费计划](https://aws.amazon.com/free/) · [账单说明](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-frequently-asked-questions-faq-billing-and-account-management.html)

## 2. 把静态 IPv4 绑到对应实例

在 **Lightsail → Networking → Create static IP** 中先选区域，再选择同一区域内的实例，点 **Create**。到实例的 **Networking** 页复核已绑定地址，把它记入自己的密码管理器或私有笔记。[AWS 静态 IP 操作说明](https://docs.aws.amazon.com/lightsail/latest/userguide/lightsail-create-static-ip.html)

| 地区 | 私下记录的入口和预期出口 | 本教程监听 | 证书名称（SNI） |
|---|---|---|---|
| 东京 | 自己的东京静态 IPv4 | UDP 443 | `jp.vpn.invalid` |
| 新加坡 | 自己的新加坡静态 IPv4 | UDP 8443 | `sg.vpn.invalid` |

SNI 是此示例证书上的名字。客户端用数字 IP 建立连接，同时用 SNI 和预先核对的指纹识别服务器，无需购买这两个名字对应的域名。

在各自实例的 **Networking → IPv4 Firewall → Add rule** 选 **Custom → UDP**，只填该实例对应端口。面向固定来源时，可把来源限制在客户端的公网地址；希望在移动网络使用时，需允许预期的移动端来源。SSH 管理入口可限制在自己的管理地址，使用 Lightsail 浏览器 SSH 时保留相应访问选项。IPv6 防火墙有单独规则。若启用了 Ubuntu 的 UFW，也要放行相同的 UDP 端口。[AWS 防火墙操作说明](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-editing-firewall-rules.html)

## 3. 在第一台空白 Ubuntu 上安装服务端

以下命令在**服务器的 SSH 终端**运行。先以新加坡为例。部署东京时，回到本节开头，把两个变量换成东京一行的值。

```bash
VPN_PORT=8443
VPN_SNI=sg.vpn.invalid
# 东京使用 VPN_PORT=443 和 VPN_SNI=jp.vpn.invalid
sudo ss -H -lunp "sport = :$VPN_PORT"
sudo ufw status
```

第一条检查应无监听输出；若已有服务占用，选一个空闲 UDP 端口，再把防火墙和客户端中的对应端口一并改好。如果 UFW 已启用，执行 `sudo ufw allow "$VPN_PORT/udp"`。在同一台主机已有 Hysteria、sing-box 或其他在用 VPN 时，先用独立测试实例或未占用的独立服务做验证。

安装官方稳定版。先下载并检查安装程序，再执行；最后记录实际版本。已有在用服务的主机请保留其版本和配置。[官方安装程序与服务管理](https://v2.hysteria.network/docs/getting-started/Server-Installation-Script/)

```bash
workdir=$(mktemp -d)
chmod 700 "$workdir"
curl -fL --proto '=https' https://get.hy2.sh/ -o "$workdir/install.sh"
less "$workdir/install.sh"
# 按 q 退出 less，确认来源和内容后执行
sudo bash "$workdir/install.sh"
hysteria version
systemctl show hysteria-server.service -p User -p Group
```

下面使用默认服务用户和同名组 `hysteria`。先用 `id hysteria` 确认；如果服务采用另一用户或组，相应替换下方的属组。每台服务器首次安装时生成自己的证书，保管好私钥。只对尚未配置的新服务执行生成步骤。

```bash
id hysteria
sudo install -d -m 0750 -o root -g hysteria /etc/hysteria/tls
# 在两份目标文件均不存在时才生成
sudo sh -eu -c '
  cert=/etc/hysteria/tls/server.crt
  key=/etc/hysteria/tls/server.key
  test ! -e "$cert"
  test ! -e "$key"
  umask 077
  openssl req -x509 -newkey rsa:3072 -nodes -sha256 -days 365 \
    -subj "/CN=$1" -addext "subjectAltName=DNS:$1" \
    -keyout "$key" -out "$cert"
  chown root:hysteria "$cert" "$key"
  chmod 0640 "$cert" "$key"
' sh "$VPN_SNI"
sudo -u hysteria test -r /etc/hysteria/tls/server.key
sudo openssl x509 -in /etc/hysteria/tls/server.crt -noout -enddate
sudo openssl x509 -in /etc/hysteria/tls/server.crt -outform DER | openssl dgst -sha256
```

记下最后一行等号后的 **64 位十六进制指纹**、所属地区和到期日。通过你已验证的 SSH 会话取得它。然后在本人的密码管理器为本节点生成独立的至少 32 字符随机口令；为方便录入分享链接，可以选择高强度随机十六进制。

打开仓库的[服务端配置模板](../examples/hysteria-server.yaml)，复制**完整内容**。在服务器执行 `sudoedit /etc/hysteria/config.yaml`，把新安装生成的示例替换为模板。修改 `listen` 为该地区的端口（如 `"0.0.0.0:8443"`），将 `REPLACE_WITH_NODE_PASSWORD` 替换为本节点的口令，检查证书和私钥路径。保留模板中的访问控制。服务端模板与客户端模板使用同一认证方式。[服务端配置字段](https://v2.hysteria.network/docs/advanced/Full-Server-Config/)

```bash
sudo chown root:hysteria /etc/hysteria/config.yaml
sudo chmod 0640 /etc/hysteria/config.yaml
sudo systemctl enable --now hysteria-server.service
systemctl is-active hysteria-server.service
sudo ss -H -lunp "sport = :$VPN_PORT"
```

看到 `active` 和预期 UDP 监听端口后，再做客户端验收。如未启动，先看 `sudo journalctl -u hysteria-server.service -n 40 --no-pager`，重点检查 YAML 缩进、端口占用及私钥读取权限。若刚编辑的服务在安装时已自动启动，执行 `sudo systemctl restart hysteria-server.service` 让它重读配置，仅操作本次新装的实例。

**第一台机器的验收。** 如果此时只建好了新加坡，可以在备用客户端中手动新增一个 Hysteria 2 节点，填入新加坡静态 IPv4、8443 端口、口令、SNI 和证书指纹，启用证书校验。发起一次新的出口查询，确认显示新加坡实例的静态 IPv4，再回到第 1 至 3 节搭建东京。两地均就绪后，按下面的方法做成一份配置。

## 4. 导入设备，一份资料包含两条线

**Windows、Android、Mac 使用 FlClash。** 从项目的最新稳定 Release 下载与系统、处理器匹配的安装包。Android 安装 APK 时仅给这次下载使用的应用安装权限，Windows 可在“设置 → 系统 → 系统信息”查看 x64 或 ARM64。用私有目录保存一份[双线客户端模板](../examples/flclash.yaml)的副本。将两地的 `JP_PUBLIC_IPV4` / `SG_PUBLIC_IPV4`、`JP_PASSWORD` / `SG_PASSWORD`、`JP_PIN_SHA256` / `SG_PIN_SHA256` 换成实际值。保持 SNI 与各自证书一致。把修改后的单个 YAML 通过私有渠道或 U 盘交给自己的设备，然后在 FlClash 的 **配置 → 添加 → 本地文件** 导入并启用，在「线路选择」中应看到「东京」「新加坡」和「自动切换」。电脑按需启用系统代理，Android 按系统提示允许 VPN 连接。[FlClash 稳定版发布页](https://github.com/chen08209/FlClash/releases/latest) · [Mihomo 的 Hysteria 2 配置](https://wiki.metacubex.one/en/config/proxies/hysteria2/)

**iPhone、iPad 或已安装小火箭的 Mac。** 使用 Shadowrocket 的 Hysteria 2 导入功能。将下面两行放入一个纯文本文件，替换六处实际值。示例假设口令仅含十六进制字符，含特殊字符的口令须做 URL 百分号编码。把两行一起复制，在支持批量粘贴的版本中从剪贴板导入；也可在可信的本地设备把两行原文制成一个二维码，私下扫描。首次导入后核对两条线路均出现、证书指纹已保留且“允许不安全”关闭。若当前版本只识别第一条，改用整段文本粘贴并再次核对；仍只导入一条时，可分别粘贴两条完成安装。iOS 的系统 VPN 配置可由小火箭经你授权后创建。[Shadowrocket 开发者的 App Store 页面](https://apps.apple.com/us/app/shadowrocket/id932747118) · [分享链接字段](https://v2.hysteria.network/docs/developers/URI-Scheme/)

```text
hysteria2://JP_PASSWORD@JP_PUBLIC_IPV4:443/?sni=jp.vpn.invalid&insecure=0&pinSHA256=JP_PIN_SHA256#Tokyo
hysteria2://SG_PASSWORD@SG_PUBLIC_IPV4:8443/?sni=sg.vpn.invalid&insecure=0&pinSHA256=SG_PIN_SHA256#Singapore
```

一份离线资料已经包含连接所需的凭据，可以在另一处网络首次导入。把它发给谁，谁就能使用其中的节点口令；配置、分享链接和二维码只通过私有渠道传输。普通分享链接表示一个节点，批量导入后可手动选线。FlClash 的自动切换按 YAML 中的代理组工作，小火箭的自动策略要在该客户端另行设置和验收。

## 5. 验收两地出口和故障切换

| 测什么 | 怎么操作 | 通过条件 |
|---|---|---|
| 真实出口 | 在备用设备上手动选东京，把测试网站流量指定经过该节点，浏览器打开 IP 查询页。切到新加坡，重新加载页面 | 两次返回的数字分别等于两地 Lightsail 静态 IPv4。[AWS IP 查询页](https://checkip.amazonaws.com/) |
| 访问质量 | 分别通过两地打开同一 HTTPS 网页、完成一次实际文件下载，间隔几分钟重复三轮 | 每轮记成功次数、总耗时、是否超时。客户端延迟数字只表示当次探测 |
| 证书校验 | 在测试设备复制一个节点，只改证书指纹的一位，手动选中副本，关闭自动回退，再发起新的 HTTPS 请求 | 正确指纹可以代理，错误指纹应失败。删除测试副本 |
| 自动切换 | 在测试设备复制完整配置，仅把首选节点端口改为已知未监听端口，选自动切换组。等过该组的健康检查周期后重新发起请求 | 新请求经备用区域，出口为其静态 IP；选回原配置后两地均可继续使用 |
| 不同接入网 | 在备用手机的 Wi-Fi 和蜂窝网络各试一次 | 分别记录两地出口和连接成功率；台式机可直接用现有网线测试 |

使用电脑的本地 HTTP 代理时，可把下面的端口改成客户端界面显示的端口，避免测到命令行的其他代理。在 Windows PowerShell 将 `curl` 换成 `curl.exe`。浏览器每条路线也要各试一次，因为分流规则可能按域名决定出口。

```bash
curl --noproxy "" --proxy http://127.0.0.1:7890 --max-time 15 https://checkip.amazonaws.com/
```

## 6. 以后怎么看账、换证书、停用

- **计费。** 在 AWS 账单的 Bills、Credits 和 Free Tier 三处分别看当期费用、抵用金和计划期限。保留 AWS 原生费用和到期提醒。[Lightsail 定价和流量规则](https://aws.amazon.com/lightsail/pricing/)
- **证书。** 在私有日历记下两地证书到期日。提前生成新的证书和私钥，在测试入口用正确和错误指纹各验一次，分发新指纹，再安排切换。保留切换窗口内可恢复的旧配置。换证书即使沿用原私钥，整张证书的 SHA-256 指纹也会改变；客户端版本升级后需重新验收。[Hysteria 客户端 TLS 字段](https://v2.hysteria.network/docs/advanced/Full-Client-Config/)
- **按人用量和暂停。** 历史部署另有每人独立账号、可暂停的网关和本机管理页，由服务端分别累计两地的流量。页面应显示核实时间，单侧读取失败时保留上次核实的合计。本文的两套个人口令适合个人多设备使用；要独立撤销某位使用者或分人计量，应在两台服务端部署独立身份与持久化计数后，再向多人发放凭据。[官方认证与计量接口](https://v2.hysteria.network/docs/advanced/Traffic-Stats-API/)
- **退出实验。** 在测试设备切回原连接，确认需要保留的数据已备份。临时停用本教程的新服务可执行 `sudo systemctl disable --now hysteria-server.service`，随后在 Lightsail 移除其专用 UDP 放行规则。要终止云资源计费，由资源所有者核对地区和实例名后，在控制台删除不再需要的实例、释放空置静态 IP，并检查快照等剩余资源与后续账单。[Lightsail 账单说明](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-frequently-asked-questions-faq-billing-and-account-management.html)
