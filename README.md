# 在 AWS Lightsail 自建新加坡与东京双节点

手机或电脑导入一份私人配置，就能在同一客户端里选择东京或新加坡出口。两个节点运行在自己的 AWS 账户中，平时使用时无需让家中的 Mac 保持开机。

## 架构

```text
iPhone / iPad / Mac（Shadowrocket）     Windows / Android / Mac（FlClash）
                        │                     │
                        └──── 一份双节点配置 ──┘
                                   │
                    ┌──────────────┴──────────────┐
                东京静态 IPv4                 新加坡静态 IPv4
                Hysteria 2 · UDP 443          Hysteria 2 · UDP 8443
                    │                              │
                东京公网出口                    新加坡公网出口
```

最早的版本在新加坡使用 WireGuard，每台设备拥有独立密钥。后来增加东京节点，并用 Hysteria 2 支持在一个客户端中选择两地出口。原项目使用 sing-box，本教程用 Hysteria 官方服务端复现双线路。两套实现的服务端配置格式不同。

## 搭建顺序

1. **准备账户。** 在 AWS 完成开户和 MFA，确认账户计划、预算及要创建的实例数。
2. **先跑通一地。** 在 Lightsail 创建一台 Ubuntu 实例，绑定同区域的静态 IPv4，配置 SSH 管理入口和该节点需要的 UDP 端口。
3. **部署第二地。** 在另一地区重复部署，每个节点分别生成口令和证书，通过已验证的 SSH 连接取得证书指纹。
4. **一次导入。** 将两个静态地址、端口、口令及指纹填入私有配置，分发到自己的设备。在客户端里逐一选中东京、新加坡，各发起一次新请求，核对实际出口。
5. **长期维护。** 保管凭据和证书到期日。每次更新先在备用设备验证，再切换日常连接。要按人暂停服务或统计用量，可在两地另接独立账号认证和服务端计量。

## 已验证的范围

原项目使用过东京和新加坡的真实云节点。仓库里的新模板另做了本机隔离测试：用两个临时服务模拟两地，手动选择每条线路都成功转发请求；错误证书指纹被拒绝。部署者仍需在自己的 AWS 实例和实际设备上核对公网出口。填写后的配置和二维码含有登录凭据，应通过私有渠道交付。
